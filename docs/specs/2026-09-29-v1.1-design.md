# AI 텍스트 어드벤처 v1.1 — 설계 문서

작성일: 2026-09-29 · 기준: v1.0 (`docs/specs/2026-09-29-text-adventure-design.md`)

## 1. 변경 요약

| 항목 | 내용 |
|---|---|
| A. 직업 | 자유 입력(비우면 AI가 정함). AI가 직업에 맞게 능력치·특기·직업 아이템 결정. 판정관이 직업을 고려해 개연성 판단 |
| B. 실패 후 전개 | 실패/불가능 시 내레이터가 이야기를 한 걸음 진전시키는 묘사 (수치 변화 없음) |
| C. 판정 개선 | 판정관에게 능력치 비공개(이중 반영 버그 수정), 주사위 표시에 성공 기준 표시 |
| D. 난이도 | 최대 체력 15, 실패 피해 0/1/2/3 |
| E. AI 수치 변화 | 판정관이 행동 성공 시 체력·능력치 변화를 스스로 판단. 코드 안전장치: 턴당 체력 ±5, 능력치 ±2, 능력치 1~9 |
| F. 한계 완화 | 묘사 온도 0.6, 등장 제한 규칙, 알려주지 않은 이름 등장 시 1회 재생성·교체, 시나리오 최소 개수 검증 |
| G. 성격 | 코드가 랜덤으로 좋은 성격 2개 + 나쁜 성격 2개 (총 100개 풀), 수치 효과 적용 |
| H. 기타 | v1.0 저장 호환, 버전 1.1.0 |

## 2. 직업 (A)

- 시작 화면에 직업 입력칸(최대 50자, 선택).
- 시나리오 스키마에 `job: { name, description, specialty }` 추가. 요청 직업이 있으면 그대로, 없으면 장르에 맞게 AI가 정함.
- 시작 능력치는 직업에 맞게 AI가 배분하되 기존대로 각 1~5, 합계 12(코드 강제).
- 시작 소지품 중 1개는 직업 아이템.
- 판정관 입력에 `직업: 이름 — 설명 (특기: …)` 추가, 규칙: "직업·특기에 맞는 행동은 확률을 높게, 맞지 않는 행동은 낮게".
- 정규화: 이름이 비면 `방랑자`.

## 3. 실패 후 전개 (B)

판정이 실패/대실패/불가능이면 내레이터 입력에 연출 지시 추가:
"정답이나 해결책을 알려주지 말되, 상황이 조금 변하거나 새로운 무언가가 눈에 띄는 등 이야기가 한 걸음 움직이도록 마무리."

## 4. 판정 개선 (C)

- `sceneFacts`에서 능력치·체력 줄 제거. 판정관 규칙에 "능력치는 코드가 반영하므로 고려하지 않음" 명시.
- 주사위 줄: `🎲 개연성 30% 민첩 +10% 성격 +15% = 55% → 주사위 23 (55 이하 성공) → ✅ 성공!`

## 5. 난이도 (D)

- 기본 최대 체력 15 (성격으로 증감, 최소 5).
- 실패 피해: low 0 / medium 1 / high 2 / deadly 3. 대실패 ×2, 현재 장소에 살아있는 적 +1, 성격 `damage_taken` 가감, 최소 0.

## 6. AI 수치 변화 (E)

해석 스키마에 추가:

```
effect_hp: -5~5              // 성공 시 플레이어 몸에 생기는 체력 변화 (먹기, 휴식, 독, 저주 등)
effect_stat: "none"|"str"|"dex"|"int"
effect_stat_delta: -2~2      // 훈련, 깨달음, 저주, 부상 등
```

- 성공·대성공·자동 성공일 때만 적용 (실패면 그 일이 일어나지 않은 것).
- 전투 피해·실패 피해·소지품 회복 아이템은 코드가 처리 → 회복 아이템을 사용한 턴에는 `effect_hp` 무시.
- 양수 `effect_hp`에는 성격 회복량 보정 적용.
- 코드 안전장치: 범위 초과 값은 잘라냄, 능력치 1~9, 체력 0~최대.

## 7. 성격 (G)

- `src/traits.js`에 100개 고정 데이터 (좋은 50, 나쁜 50). 새 게임 시 코드 RNG로 좋은 2 + 나쁜 2 추첨. 같은 `group`(반대 성격 쌍 등)은 중복 추첨 안 됨.
- 효과 부품:

| 키 | 의미 |
|---|---|
| `str` `dex` `int` | 시작 능력치 가감 (적용 후 1~9로 자름) |
| `max_hp` | 최대 체력 가감 |
| `crit` | 대성공 범위 가감 (기준: max(1, floor(확률/5)) + crit, 확률 이하로 제한) |
| `fumble` | 대실패 범위 가감 (기준: 주사위 ≥ 96 - fumble) |
| `damage_taken` | 실패 시 받는 피해 가감 |
| `attack_damage` | 공격 성공 피해 가감 (최소 1) |
| `heal` | 회복량 가감 (회복 아이템, 양수 effect_hp) |
| `vs_enemy` | 살아있는 적이 있는 장소에서 판정 확률 가감 |
| `action.{move,take,use,attack,talk,examine,other}` | 해당 행동의 판정 확률 가감 |

- 판정 확률: `clamp(기본 + (능력치-3)×5 + 아이템 + 성격, 1, 99)`. 성격 보너스 = `action[행동] + (적 있으면 vs_enemy)`.
- 성격은 판정관에게 알리지 않음(이중 반영 방지). 내레이터에게 이름을 전달해 묘사에 녹임.
- 밸런스 검증: 점수 = 10×능력치합 + 3×max_hp + 5×crit − 3×fumble − 10×damage_taken + 10×attack_damage + 5×heal + vs_enemy + Σaction. 좋은 성격 > 0, 나쁜 성격 < 0.
- 화면: 게임 시작 시 성격 공개, 상태창에 성격 목록(좋음 초록/나쁨 빨강)과 효과 요약.

## 8. 한계 완화 (F)

- 스트리밍 기본 온도 0.8 → 0.6.
- 내레이터 규칙: "[지금 상황]과 이야기 기록에 없는 인물·적·아이템을 새로 등장시키지 않음", "성격을 묘사에 녹임".
- 이름 검사 `unknownNames(text, state, messages)`: 시나리오의 아이템·적·NPC 이름(2자 이상) 중 묘사에 나왔지만 AI에게 준 메시지(시스템 메시지의 숨겨진 진실은 제외)에 없는 이름. 있으면 조용히 1회 재생성 → `{type:'replace', target, text}` 이벤트로 화면 문단 교체. 에필로그에도 적용.
- 시나리오 검증 최소 개수: 아이템 5, 적 2, NPC 1.

## 9. 데이터·API 변경

- `player`에 `job`, `traits`(전체 객체 사본) 추가. `max_hp`는 성격 반영값.
- `publicState`에 `job`, `traits: [{ name, description, good, summary }]` 추가.
- `POST /api/new { genre, job }`.
- 턴 결과 `result`에 `traitBonus` 추가.
- v1.0 저장 호환: `traits` 없으면 `[]`, `job` 없으면 `null`.

## 10. 테스트

- traits: 100개/50·50, id·이름 유일, 효과 키 유효, 점수 부호, 추첨 결과(좋음2·나쁨2·그룹 중복 없음), 효과 요약 문구, 합산
- rules: 성격 적용 초기 상태, 성격 판정 보너스, crit/fumble 범위, 피해·공격·회복 가감, AI 효과 적용·범위·실패 시 미적용·회복 아이템 턴 무시, 새 피해표
- prompts: 판정관에 능력치 없음·직업 포함, 내레이터 성격·연출 지시(실패 시만), unknownNames
- scenario: job 정규화·기본값, 최소 개수 검증, 직업 요청 전달
- game: 성격 추첨·직업 전달, 이름 검사 교체 이벤트
- llm: 스트리밍 온도 0.6
- 수동: 직업 입력 게임 생성, 성격 표시, 직업 행동 개연성, 수치 변화 행동, 실패 묘사
