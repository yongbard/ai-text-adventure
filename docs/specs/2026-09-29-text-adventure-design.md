# AI 텍스트 어드벤처 — 설계 문서

작성일: 2026-09-29

## 1. 개요

로컬 LLM(Ollama + `gemma4:12b`)으로 돌아가는 1인용 텍스트 어드벤처.
플레이어가 자유롭게 행동을 입력하면 **AI가 개연성(성공 확률)을 판단 → 코드가 주사위로 판정 → AI가 결과에 맞춰 이야기를 이어 쓰는** 구조.
수치·사실(체력, 소지품, 지도, 엔딩)은 코드가 관리하고, AI는 해석과 묘사만 담당한다.

- 실행: Node.js 서버(외부 의존성 없음) + 브라우저 화면
- 환경: Windows, RTX 5070 Ti Laptop(VRAM 12GB), 측정 속도 약 40 tok/s
- 비용: 없음 (전부 로컬)

## 2. 게임 흐름

1. **시작 화면**: 장르 프리셋 3종(다크 판타지 / 좀비 생존 / 우주선 SF) 또는 직접 입력. 자동 저장이 있으면 [이어하기].
2. **시나리오 생성** (1회): AI가 JSON으로 생성 → 코드 검증 → 실패 시 최대 3회 재생성.
3. **턴 진행**: 자유 입력 → 4단계 처리(§3) 반복.
4. **엔딩** (코드가 판정, 매 턴 후 확인)
   - 승리: 목표 아이템 소지 + 목표 장소 도착 + 보스 처치
   - 사망: 체력 0
   - 시간 초과: 60턴 경과
   - 엔딩 시 AI가 에필로그 작성 + 숨겨진 진실 공개 + 통계(턴 수, 주사위 기록, 대성공/대실패 횟수)

### 2.1 시나리오 데이터 (비밀 장부)

```
title, premise(공개 도입부), truth(숨겨진 진실), goal(목표 설명)
start_location_id, goal_item_id, goal_location_id, boss_enemy_id
player: { stats: {str, dex, int} (각 1~5, 합 12), hp: 10, max_hp: 10, inventory: [item_id] }
locations(8~12): { id, name, description, exits: [{ to, requires_item_id|null }] }
items: { id, name, description, location_id|null(=시작 소지품), heal: 0~5 }
enemies(2~4, 보스 포함): { id, name, location_id, hp: 1~6(보스 6) }
npcs(1~2): { id, name, location_id, personality, knowledge(힌트) }
```

**검증 규칙**
- 모든 장소가 시작 장소에서 도달 가능(잠긴 통로는 열쇠 아이템이 잠긴 곳 너머에 있지 않아야 함)
- 목표 아이템이 존재하고 도달 가능한 장소에 있음
- 보스가 목표 장소에 있음
- 모든 id 참조가 유효함, 능력치 합 12, 수치가 범위 안
- 범위를 벗어난 수치는 거부가 아니라 범위로 보정, 참조 오류·도달 불가는 재생성

## 3. 턴 처리

### 1단계 — 해석 (AI, 구조화 출력)

```
{
  action: "move" | "take" | "use" | "attack" | "talk" | "examine" | "other",
  target: string | null,          // 장소/아이템/적/NPC 이름
  items_used: string[],           // 사용하는 소지품 이름
  trivial: boolean,               // 당연히 되는 행동(둘러보기, 대화, 소지품 확인)
  base_chance: 1~99,              // 개연성 기반 기본 확률
  reason: string,                 // 확률 판단 이유(한 문장)
  stat: "str" | "dex" | "int",
  item_bonus: 0~20,
  risk: "low" | "medium" | "high" | "deadly"
}
```

### 2단계 — 판정 (코드)

**불가능(0%, 주사위 없음, 턴 소모)**
- `items_used`에 소지하지 않은 아이템 → "없다"로 처리
- `move` 대상이 현재 장소와 연결되지 않음, 또는 필요한 열쇠 아이템 미소지
- `take` 대상이 현재 장소에 없음 / `attack` 대상이 현재 장소에 없거나 이미 처치됨

**자동 성공(주사위 없음)**: `trivial = true`

**확률 계산**
```
최종 확률 = clamp(base_chance + (능력치 - 3) × 5 + item_bonus, 1, 99)
```
(능력치 보정 -10 ~ +10, item_bonus는 0~20으로 자름)

**주사위**: 1~100

| 등급 | 조건 |
|---|---|
| 대성공 | roll ≤ max(1, floor(확률 / 5)) |
| 성공 | roll ≤ 확률 |
| 대실패 | roll ≥ 96 이고 실패 |
| 실패 | 그 외 |

### 3단계 — 결과 반영 (코드)

**성공 시 효과**
| action | 효과 |
|---|---|
| move | 대상 장소로 이동, 방문 기록 |
| take | 아이템을 소지품으로 |
| attack | 적 체력 -2 (대성공 -4), 0 이하면 처치 |
| use | 회복 아이템(heal>0)이면 체력 회복(최대치까지) 후 소모 |
| talk / examine / other | 수치 변화 없음 (묘사로만) |

대성공 추가 보상: 체력 +1 (최대치까지).

**실패 시 피해**: risk 기준 low 1 / medium 2 / high 3 / deadly 4, 대실패는 ×2.
현재 장소에 살아있는 적이 있으면 +1. `trivial`과 불가능 처리는 피해 없음.

**기록**: 턴 +1, 사건 한 줄 요약 추가(예: `12턴: 경비병 공격 → 실패, 체력 -2`).
엔딩 조건 확인.

### 4단계 — 묘사 (AI, 스트리밍)

AI에게 주는 입력: 판정 결과(맨 앞에 강조) + 수치 변화 + 현재 장소 정보(장소 설명, 출구, 아이템, 적, NPC. `talk` 대상 NPC의 knowledge 포함) + 최근 6턴 원문 + 사건 요약 전체.
AI는 결과를 바꿀 수 없고, 왜 그렇게 되었는지 그럴듯하게 채워 넣는다. 3~5문장.

## 4. 프로그램 구조

```
server.js          HTTP 서버, 정적 파일, API
src/rules.js       순수 함수: 확률, 주사위, 판정, 상태 반영, 엔딩 (RNG 주입)
src/scenario.js    시나리오 생성 요청 + 검증
src/game.js        턴 오케스트레이션 (해석 → 규칙 → 묘사 → 저장), LLM 주입 가능
src/llm.js         Ollama /api/chat 호출 (구조화 출력, 스트리밍, 재시도)
src/prompts.js     해석 / 묘사 / 시나리오 / 에필로그 지시문
src/save.js        saves/autosave.json 원자적 저장(임시 파일 → rename)
public/            index.html, style.css, app.js
test/              node:test 테스트
```

**Ollama 설정**: `num_ctx: 16384`, `keep_alive: "30m"`, `think: false`, 해석·시나리오는 `format`에 JSON 스키마 지정.

**API**
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/status | Ollama 연결 여부, 모델 존재 여부, 저장 파일 유무 |
| POST | /api/new | `{ genre }` → 시나리오 생성, 공개 상태 반환 |
| GET | /api/load | 저장된 게임의 공개 상태 + 이야기 기록 |
| POST | /api/turn | `{ input }` → NDJSON 스트림: `roll` → `text`(여러 번) → `state` |

**공개 상태**(브라우저로 가는 정보): 제목, 도입부, 목표 설명, 턴, 체력, 능력치, 소지품, 현재 장소 이름·출구 이름, 방문한 장소 목록, 이야기 기록, 엔딩 여부.
진실, 안 가본 장소, 적 체력, NPC knowledge는 보내지 않는다(엔딩 시 진실만 공개).

## 5. 화면

- 좌측 이야기 창: 입력(▶), 주사위 줄(🎲 개연성 30% + 민첩 10% = 40% → 주사위 23 → ✅ 성공!), 묘사(실시간 출력)
- 우측 상태 창: 체력 바, 능력치, 현재 장소·출구, 소지품(신규 강조), 가본 곳, 턴 n/60
- 주사위 연출 약 1초, 대성공 금색 / 대실패 빨강
- 처리 중 입력 잠금
- 시작 화면 / 엔딩 화면(에필로그, 진실, 통계, 새 게임)
- 어두운 테마, 본문 세리프 글꼴

## 6. 오류 처리

| 상황 | 대응 |
|---|---|
| Ollama 미실행 / 모델 없음 | 시작 화면에 안내 |
| 첫 모델 로딩(~100초) | "AI를 깨우는 중..." 표시 |
| 해석 JSON 오류 | 2회 재시도 → 실패 시 "다르게 표현해 주세요", 턴 미소모 |
| AI 수치 범위 초과 | 코드가 보정 |
| 시나리오 검증 실패 | 최대 3회 재생성 → 실패 시 오류 표시 |
| 묘사 실패 | 판정 유지, 코드가 대체 문장 생성 |
| 저장 파일 손상 | 원자적 저장으로 예방, 읽기 실패 시 새 게임 안내 |

알려진 한계: 묘사의 뉘앙스가 판정과 어긋날 가능성은 완전히 막지 못함. 🎲 줄이 항상 실제 결과를 표시.

## 7. 테스트

1. `rules.js` 단위 테스트(고정 시드 RNG): 확률 보정과 1~99 제한, 등급 경계값, 불가능 판정, 피해 계산, 회복, 전투, 엔딩 조건
2. `scenario.js` 검증기 테스트: 끊긴 지도, 목표 누락, 잠긴 열쇠 순환, 잘못된 참조
3. `game.js` 흐름 테스트(가짜 LLM): 턴 순서, JSON 오류 재시도, 묘사 실패 대체, 저장
4. 수동 플레이: 프리셋 3종 각각 몇 턴, 턴당 시간 측정

멀티 세이브 슬롯, 미니맵 그림, 효과음, 모바일 최적화, 여러 모델 선택 UI.
